# Архитектура — REFAL Basketball League

## 1. Обзор

Трёхуровневое приложение:

```
Браузер (мобайл-first)
   │  HTTPS
Next.js App Router (SSR + Server Actions/Route Handlers)
   │  Supabase JS (anon key, сессия пользователя)   │  service role (только сервер)
Supabase: PostgreSQL + RLS + Auth(MFA) + Realtime
```

Ключевой принцип: **база данных — последняя линия обороны.** Любая проверка прав
дублируется в Postgres (RLS + `SECURITY DEFINER` функции), поэтому обход UI или
прямой запрос к PostgREST не даёт доступа к закрытым данным.

## 2. Роли (RBAC)

| Роль | Механизм | Права |
|---|---|---|
| Посетитель | `anon` | только `public_*` представления |
| Оператор | `authenticated`, `app_users.role='operator'` | события назначенных матчей (через функции), чтение составов этих матчей |
| Администратор | `authenticated`, `app_users.role='admin'` + MFA | полное управление |

`app_users` — каноническая таблица идентичности/ролей (ссылается на
`auth.users`). Она покрывает сущности спецификации `admin_users` (role='admin')
и идентичность операторов.

## 3. Модель данных

Полная схема — в [`supabase/migrations/0001_schema.sql`](../supabase/migrations/0001_schema.sql).

Группы сущностей:

- **Турнир:** `tournaments`, `tournament_settings`, `tournament_groups`
- **Участники:** `teams`, `players` (внутренние ПДн), `private_player_contacts`
  (телефон/email — максимальная защита), `team_memberships` (история)
- **Матчи:** `matches`, `match_periods`, `match_events` (единый источник счёта),
  `match_results` (официальный снимок), `bracket_slots` (плейсхолдеры плей-офф)
- **Результаты:** `standings` (производная таблица)
- **Доступ:** `app_users`, `operator_assignments`
- **Приватность:** `consent_text_versions`, `consent_tokens`, `consent_records`,
  `privacy_requests`
- **Аудит:** `audit_logs`

### Единый источник истины для счёта

`match_events.points` — это `GENERATED ALWAYS AS (...) STORED` колонка: очки
вычисляются из типа события и флага попадания. Оператор физически не может
изменить счёт в отрыве от зафиксированного броска (спец. §8). Счёт команды =
сумма `points` по незаблокированным (`not voided`) событиям.

### Производные данные

`standings` пересчитывается ТОЛЬКО функцией `recompute_standings()` после
подтверждения результата — показатели не хранятся в нескольких независимо
изменяемых местах (спец. §15).

## 4. Серверные функции (БД)

См. [`0002_functions.sql`](../supabase/migrations/0002_functions.sql). Все
мутирующие функции — `SECURITY DEFINER` с собственной проверкой прав внутри.

| Функция | Кто | Назначение |
|---|---|---|
| `apply_match_event(...)` | оператор/админ | **идемпотентная** запись события |
| `void_match_event / undo_last_event` | оператор/админ | мягкая отмена с причиной |
| `start_match / advance_period` | оператор/админ | жизненный цикл матча |
| `submit_match_result` | оператор/админ | отправка на подтверждение |
| `confirm_match_result` | админ | подтверждение → пересчёт таблицы и сетки |
| `recompute_standings` | внутр. | пересчёт таблицы с тай-брейками |
| `resolve_bracket` | внутр. | подстановка команд в плей-офф |
| `create_consent_token` | админ | выдача одноразового токена (хранится хэш) |
| `record_consent` | `anon` по токену | фиксация согласия игроком |
| `revoke_consent` | админ | отзыв согласия |

### Идемпотентность LIVE

`apply_match_event` принимает `client_event_id` (UUID, генерируется клиентом).
Уникальный индекс `(match_id, client_event_id)` + `on conflict do nothing`
гарантируют, что повтор запроса при потере сети не удвоит счёт (спец. §8, §11.10).

## 5. Приватность по умолчанию

Базовые таблицы с ПДн закрыты RLS без политики для `anon`. Публичный сайт читает
только представления `public_*`:

- `public_players` / `public_player_stats` раскрывают реальное имя лишь при
  активном согласии `publish_name`; индивидуальную статистику — лишь при
  `publish_stats`. Иначе — псевдоним или «Игрок №N».
- `private_player_contacts` не входит ни в одно представление.

Детали — в [`docs/SECURITY.md`](SECURITY.md).

## 6. Фронтенд

- `src/lib/supabase/{client,server,admin}.ts` — три клиента (браузер/сервер/
  сервис-роль). Сервис-роль защищён импортом `server-only`.
- `src/lib/queries.ts` — все чтения публичных данных.
- `src/lib/auth.ts` — резолв текущего пользователя/роли и проверка MFA (aal2).
- `src/proxy.ts` — обновление сессии + первичный gate для `/admin` (не является
  самостоятельной защитой; авторитетны RLS и проверки на странице).
- Строгая CSP и заголовки безопасности — в `next.config.ts`.

## 7. Расписание (планируется, §7)

Генератор поддержит round-robin, группы+плей-офф и single-elimination с
ограничениями: нет одновременных матчей команды/площадки, соблюдение отдыха,
проверка влезания в месяц, предпросмотр перед публикацией, ручная правка с
контролем конфликтов, сохранение сыгранных результатов.

## 8. Решения и допущения

- **Хостинг:** Supabase Cloud (по выбору заказчика) для dev и prod. Трансграничная
  передача задокументирована как остаточный риск (ст. 89 КР).
- **Тай-брейки:** реализован детерминированный порядок (очки → личные встречи для
  пар → разница → заброшенные → победы). Для ничьих >2 команд данные личных встреч
  выводятся админу для решения по регламенту.
- **Ничьи:** по умолчанию выключены (`overtime_enabled`), т.к. баскетбол играет
  овертаймы; настраивается в `tournament_settings`.
