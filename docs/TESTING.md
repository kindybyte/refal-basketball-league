# Тестирование — REFAL Basketball League

## 1. Юнит-тесты (бизнес-логика)

```bash
npm test          # разовый прогон
npm run test:watch
```

Покрывают:

- **Генератор расписания** (`src/lib/scheduling/generator.test.ts`): круговой
  турнир (каждая пара встречается один раз), нечётное число команд, несколько
  кругов, распределение по группам, отсутствие конфликтов команд/площадок,
  соблюдение отдыха, порядок «плей-офф после группового этапа», корректная
  ошибка при невозможности уместить календарь.
- **Статистика** (`src/lib/stats.test.ts`): средние за игру, проценты бросков,
  отсутствие расчёта процентов без попыток, нулевые значения без игр.

## 2. Проверки безопасности БД (spec §11.10)

Скрипт `supabase/tests/security_checks.sql` запускается в **Supabase SQL
Editor** (всё в транзакции с откатом — данные не остаются). Проверяет:

| Проверка | Ожидание |
|---|---|
| Счёт из событий (generated column) | трёхочковый → ровно 3 очка |
| Идемпотентность | повтор `client_event_id` отклонён |
| Публикация имени по согласию | скрыто → показано после согласия → скрыто после отзыва |
| Анонимный доступ к `players` | 0 строк или отказ |
| Анонимный доступ к `private_player_contacts` | 0 строк или отказ |
| Анонимный доступ к публичным VIEW | разрешён |

Успешный прогон печатает серию `PASS: …` и завершается без ошибок.

## 3. Проверки доступа через REST (истинный анонимный клиент)

Эти проверки используют **anon-ключ** и публичный REST, т.е. воспроизводят то,
что реально видит браузер посетителя. Подставьте свой `PROJECT` и `ANON_KEY`.

```bash
BASE="https://PROJECT.supabase.co/rest/v1"
ANON="apikey: ANON_KEY"

# Должно быть пусто/ошибка — анонимный доступ к ПДн закрыт:
curl -s "$BASE/players?select=first_name,last_name" -H "$ANON"
curl -s "$BASE/private_player_contacts?select=phone,email" -H "$ANON"

# Должно работать — публичные представления без ПДн:
curl -s "$BASE/public_matches?select=home_label,away_label,home_score" -H "$ANON"
curl -s "$BASE/public_standings?select=team_name,tournament_points" -H "$ANON"

# IDOR: подстановка чужого id в публичном профиле не раскрывает скрытое имя
curl -s "$BASE/public_players?player_id=eq.SOME_UUID&select=display_name,name_is_public" -H "$ANON"
```

Ожидаемо: первые два запроса возвращают `[]` или ошибку доступа; публичные —
данные без персональных полей.

## 4. Ручной сквозной сценарий (приёмка §19)

1. Создать турнир → добавить команды и игроков.
2. Выдать ссылку согласия, подтвердить публикацию имени → имя появляется на сайте.
3. Отозвать согласие (или через `revoke_consent`) → имя исчезает из публичных
   ответов.
4. Сгенерировать и опубликовать расписание на месяц без конфликтов.
5. Назначить оператора → вести матч с телефона → отправить результат.
6. Подтвердить результат → таблица и рейтинги пересчитались.
7. Проверить, что посетитель видит актуальное расписание и live-счёт.

## 5. Замечания

- Юнит-тесты не требуют БД. Проверки RLS/согласий требуют подключения к
  Supabase (SQL-скрипт или REST с anon-ключом).
- Прогоняйте проверки безопасности из разделов 2–3 **перед каждым запуском** с
  реальными данными.
