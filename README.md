# REFAL Basketball League

Веб-приложение для баскетбольного турнира на площадке «Рефал» (Бишкек, Кыргызстан).
Мобайл-first, с LIVE-ведением матчей, турнирной таблицей и строгой защитой
персональных данных.

> **Главный приоритет — конфиденциальность.** Публичный сайт получает данные
> только через consent-aware представления (`public_*`). Имена, контакты и
> персональная статистика не попадают в браузер без действующего согласия
> игрока. См. [`docs/SECURITY.md`](docs/SECURITY.md).

## Стек

- **Frontend:** Next.js 16 (App Router) · React 19 · TypeScript · Tailwind CSS 4
- **Backend:** Supabase (PostgreSQL · Auth c MFA · Realtime · RLS)
- **Тесты:** Vitest

## Быстрый старт

### 1. Зависимости

```bash
npm install
```

### 2. Проект Supabase

1. Создайте проект на [supabase.com](https://supabase.com).
2. Скопируйте `.env.local.example` → `.env.local` и заполните:
   - `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` — из Project Settings → API;
   - `SUPABASE_SERVICE_ROLE_KEY` — там же (хранить только на сервере!).

> ⚠️ **Трансграничная передача (ст. 89 Цифрового кодекса КР).** Supabase Cloud
> хранит данные вне Кыргызстана. Это осознанный остаточный риск — перед работой
> с реальными ПДн обеспечьте правовое основание передачи. См. `docs/SECURITY.md`,
> раздел 9.

### 3. Применение миграций

Миграции лежат в `supabase/migrations/` и применяются по порядку.

**Вариант A — SQL Editor (без доп. инструментов):**
Откройте Supabase → SQL Editor и выполните файлы по очереди:
`0001_schema.sql` → `0002_functions.sql` → `0003_rls_and_views.sql` →
`0004_seed_demo.sql` → `0005_public_extras.sql`.

После применения прогоните `supabase/tests/security_checks.sql` — он должен
завершиться `ALL SECURITY CHECKS PASSED`.

**Вариант B — Supabase CLI:**
```bash
npm i -g supabase
supabase link --project-ref <project-ref>
supabase db push
```

### 4. Первый администратор

Создайте пользователя в Supabase → Authentication → Users, затем в SQL Editor:

```sql
insert into public.app_users (id, role, full_name)
values ('<auth-user-uuid>', 'admin', 'Главный администратор');
```

Включите MFA для этого пользователя (обязательно для админов, спец. §11.7).

### 5. Запуск

```bash
npm run dev
```

Откройте http://localhost:3000. Пока не настроен `.env.local`, публичные
страницы показывают уведомление о настройке вместо падения.

## Демо-данные

Миграция `0004_seed_demo.sql` создаёт **явно помеченный** демо-турнир с 8
вымышленными командами (`is_demo = true`, синтетические имена — не реальные ПДн).
Удалите демо-турнир из панели перед реальным турниром.

## Критерии готовности (§19)

| Критерий | Как реализовано |
|---|---|
| Админ создаёт команду и регистрирует игроков | `/admin/teams`, `/admin/players` |
| Календарь на месяц без конфликтов | `/admin/schedule` + генератор (18 тестов) |
| Посетитель видит актуальное расписание | `/schedule`, `/matches` |
| Оператор ведёт матч с телефона | `/admin/matches/[id]/control` (мобайл-first) |
| Счёт и статистика в реальном времени | события + live-поллинг на `/matches/[id]` |
| Таблица пересчитывается после подтверждения | `confirm_match_result` → `recompute_standings` |
| Несанкционированный не может изменить данные | RLS + `SECURITY DEFINER` функции |
| Закрытые данные недоступны публично | `public_*` VIEW, контакты вне представлений |
| Согласие можно подтвердить и отозвать | `/consent/[token]`, `revoke_consent` |
| Автопроверки безопасности | `supabase/tests/security_checks.sql`, `docs/TESTING.md` |

Полный сценарий приёмки — в [`docs/TESTING.md`](docs/TESTING.md) §4.
